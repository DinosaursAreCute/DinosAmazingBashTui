DABT markupPhase3 Review

Framework review · early alpha · 10 October 2026

DABT on devex/markupPhase3

Dino's Amazing Bash TUI, read from the branch itself this time: cloned, checked out, test suites run, and its companion extension and three example apps inspected. It is a surprisingly large animal for a five-week-old egg.

branch devex/markupPhase3 @ 9f774bd (8 Oct) forks from main v0.0.23, +13 commits, 0 behind VERSION 0.0.24-preRelease lib/ 29,465 lines of Bash
Today6.2/10
Potential7.5/10

The most capable shell-native TUI framework I could find, built with real engineering discipline, but its "pure Bash + POSIX" tagline really means "Bash 5 on a Linux box", and one person carries all of it. Superpower: a whole windowed, multi-page app (floating windows, modals, persistent shells, resizable panes) declared in XML and styled with CSS, sourced into a Bash script with nothing to compile or install.

Biggest strengths

  1. HIGH A declarative markup system with templates, components, loops, conditionals, addons, and now shells, layers and pane resize/collapse. No other shell tool has a component model.
  2. HIGH Engineering discipline unusual for an alpha: 925 unit tests plus golden frames, an XSD kept in step by a test, a validator, a TUI_CACHES=off parity mode for cache bugs.
  3. MED Measurement-driven performance work with published plans, fork budgets and before/after numbers.

Biggest weaknesses

  1. HIGH The portability claim. Bash 5 is woven through the core with no version guard, tui.exec depends on util-linux script -c, and display width ignores wide characters and non-UTF-8 locales.
  2. HIGH Bus factor of one, and contributions are closed.
  3. MED Safety nets with holes: no EXIT trap (an exit leaves the terminal raw), CI never runs the 925 unit tests or touches this branch, and the editor extension's markup completion breaks on this branch's schema.

What makes it special

the spotlight

Genuinely novel

Markup HIGH

A component model in Bash

<template>, <use>, <slot>/<fill>, <component>, <for>, <if>, parameterised includes, and tui.page.refresh rebuilding only changed panes. dialog, gum and bash-tui-toolkit are one-widget-per-call tools. Nothing in the shell world composes like this.

New on branch HIGH

A window system in XML

<window>, <modal>, <popup>, <tooltip>, <contextmenu> and <toast> layers that drag, resize, snap to edges, hold focus as modal scopes, and detach or dock panes. Few TUI libraries in any language offer draggable windows as a built-in, declarative tag. Here it is one.

New on branch MED

Shells: an app layout that persists

<tui shell="_shell.xml"> with an <outlet/> is the web's layout-route idea. Navigating keeps the menu's focus, typed values, timers and scroll, and the page is cached as a delta over the shell. The author's bench puts two in-shell switches at 23.5 ms against 29.2 ms.

Markup MED

Addons that patch pages

Addon files append, replace, wrap or set nodes in another page by selector and priority. DabTop uses addons plus <if> to toggle its boxes at runtime, which shows the idea working outside the demo.

Bash version HIGH V

Bash 5.0 is a hard floor

lib/ has 211 declare -A/-gA, 51 namerefs, 25 uses of EPOCHREALTIME (5.0), 146 printf -v, fractional read -t, {fd}> redirections and ${x^^}. The README's "Bash 5.0+" is accurate. There is no BASH_VERSINFO check anywhere, so macOS's stock Bash 3.2 dies on the first declare -gA with a cryptic "invalid option" I.

macOS with Homebrew Bash MED I

Mostly plausible, one hole

The stat shim, the /proc fallbacks, stty size and fractional sleep all work on macOS. tui.exec is the one feature I expect to break, because of script -c. That makes "Linux first, macOS with Homebrew Bash 5 except the terminal pane" a fair description.

Probe of _tui._vwidth_v on the branch V. In a UTF-8 locale, CJK and emoji are undercounted, so rows overflow their panes. Parse, expand, validate, build, cache, then lay out, paint, diff and flush once. The costly Bash work (forks, parsing) is pushed to load time and memoised against keys that include every input, and the TUI_CACHES=off switch exists to prove both paths draw the same thing. That is the best structural decision in the project HIGH. The weak spot is the edge between async painters and the main loop: both write to the terminal, and the author's own notes say an interleaved write "is not ruled out" LOW.

Performance, by the author's numbers

not re-measured

Users will notice the first launch after an edit, and little else. Interactions land in the 30–50 ms range, page switches sit around 100–150 ms, and a cold start after cache invalidation costs about 3.4 seconds.

Where the methodology looks thin. I took these numbers as given and did not validate them, but a reader should know their limits.
  • No full profiler run is published for this branch. Its figures are micro-benches, and goto_pair_* is "load only, no render", so it understates what a user sees.
  • The author notes the latest v0.0.23 page-switch run was taken while editing on the same machine, so it is an upper bound with noise.
  • tools/bench/baseline.txt was not regenerated after the layer work, so bench comparisons on this branch are against a stale baseline.
  • The committed reports stop at 30 September, so the 1–2 October runs quoted in the changelog can't be reproduced from the repo.
  • Cold start warms pages in parallel, capped at nproc I. 3.38 s is one machine's number; a 2–4 core laptop will likely be slower.

The trajectory is the encouraging part. The branch's own plan lists 15 items with expected and real gains. Three have landed (the refresh cache job went from 422 to 211 ms of CPU; 6 and 3 forks were removed from clicks and palette opens). The author's diagnosis that sub-100 ms switches need persistent shells rather than more tuning is honest, and it marks a structural ceiling MED.

# lib/core/tui_loop.sh:13–19
_tui._secs_to_us() {
	local s="$1" whole frac
	whole="${s%%.*}"
	frac="${s#"$whole"}"
	frac="${frac#.}000000"
	printf -v "$2" '%d' \
	  "$((10#${whole:-0} * 1000000 + 10#${frac:0:6}))"
}
✔ GOOD · fork-free arithmeticlib/core/tui_loop.sh

Bash has no floats, and the lazy fix is $(awk …), which forks on every tick. This converts "0.05" seconds to microseconds with parameter expansion, forces base 10 so "08" isn't read as octal, and writes into a named variable. Small, correct, and typical of the fork discipline across the code.

# lib/tui.sh:153–166
_tui_proc_tree() {
	local child kids=""
	if [[ -r "/proc/$1/task/$1/children" ]]; then
		read -r kids <"/proc/$1/task/$1/children" 2>/dev/null
	else
		kids="$(pgrep -P "$1" 2>/dev/null)"
	fi
	for child in $kids; do
		_tui_proc_tree "$child"
	done
	_TUI_PTREE+=("$1")
}
✔ GOOD · fast path with a fallbacklib/tui.sh

Uses the Linux kernel file when it exists (no fork) and falls back to pgrep elsewhere. Children come before parents, so the tree can be killed bottom-up. This is the right shape for every Linux-only shortcut in the project.

The companion extension: DABT Tools

It is a VS Code extension written in TypeScript, despite the "Plugin" repo name, and not a DABT runtime plugin. It has 2,892 lines of source, 4 commits (22–23 September) and installs from a .vsix. It provides 7 lint rules (private _tui.* calls, _TUI_TICK_FN clobbering, the | while read subshell trap), completion and hover for every tui.* function, inlay hints for positional arguments, XML completion from tui.xsd, theme-aware colour swatches on class=, go-to-definition from action=, a page scaffolder, CLI commands and a subshell/fork counter. For Bash, which gives no signature feedback at all, this is a large DX gain HIGH.

Compatibility with this branch: partly broken. V I ran the extension's own parsers (the ones it uses for live scanning) against both checkouts. The API side copes: it scans lib/ recursively and finds 941 public functions on the branch. The XSD side does not: the branch moved pane attributes into a shared <xs:attributeGroup>, and the parser only reads inline <xs:attribute> tags.
Parsed by the extensionmain v0.0.23devex/markupPhase3

So on this branch, <pane> loses completion for split, weight, border and the new resize/collapse attributes, and the new layer tags get none. Resolving attributeGroup ref= in parseDabtXsd.ts fixes it, which is an hour's work HIGH for DX.

Roadmap for the author

impact ÷ effort, quick wins first

Quick wins: minutes to an hour

  1. Trap EXIT and HUP. trap '_master_cleanup' EXIT HUP next to the INT/TERM trap, guarded so cleanup runs once. Then drop the trailing stty sane, which overwrites the user's own settings you just restored.
    HIGHminutes
  2. Add a Bash version guard at the top of lib/tui.sh: if BASH_VERSINFO[0] < 5, print "DABT needs Bash 5+ (you have …); on macOS: brew install bash" and stop.
    HIGHminutes
  3. Restate the claim. "Pure Bash 5 plus standard Unix tools. Linux first; macOS with Homebrew Bash, except the terminal pane." Fix the "five themes" line while there.
    HIGHminutes
  4. Resolve xs:attributeGroup refs in the extension's XSD parser so panes and layers get completion on this branch.
    HIGHan hour
  5. Run tools/t.sh and the golden tests in CI, on devex/* branches too. The best test suite in the project currently guards nothing automatically.
    MEDan hour
  6. Warn on a non-UTF-8 locale at startup, or fall back to ASCII borders. It turns a broken layout into a clear message.
    MEDan hour
  7. Fix the $HOME leak in the job tests and give the runner a guard that recreates or asserts the sandbox between tests.
    LOWan hour
  8. Anchor the attribute regex in _tui_parse.attr_valuev, and delete the committed GNU manual.
    LOWminutes

Short projects: a day or a few

  1. Make tui.set redraw, or rename the silent variant (tui.set_silent), with a one-release deprecation shim.
    MEDa day
  2. Publish a deep profiler run per branch and regenerate the bench baseline. Include the core count, since cold start scales with nproc.
    MEDa day
  3. Give tui.exec a BSD path (script -q /dev/null sh -c "$cmd") and honour $TMPDIR; add a macOS runner with Homebrew Bash to CI.
    MEDa day
  4. Add a wcwidth table to _tui._vwidth_v (East Asian Wide, emoji, zero-width and combining marks), audit direct ${#…} width uses, and add golden frames with CJK text.

    HIGHprocess

    HIGHsocial

    HIGHweeks
